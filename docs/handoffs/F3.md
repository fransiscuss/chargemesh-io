## Extension points and decisions

- Router constructs a fresh `FrameContext` per received frame. It resolves action
  and response latency before handing the context to the pipeline.
- Async observers receive the original parse result/raw traffic and the final
  delivery metadata; rewrites change outbound serialization only.
- `delivery.forwardedTo` contains the primary UUID or the literal `charger`.
- Unparseable input is forwarded unchanged, with `ParseResult.ok=false`. F4 must
  settle its event-envelope representation (see spec Open questions) and retain raw.
- No recorder, EventBus, mirror routing, configuration cache, or dashboard exists yet.
- Fly's non-overridable `Fly-Forwarded-Proto` is trusted only with the explicit
  `trustFlyProxy` option; executable startup enables it when `FLY_APP_NAME` is set.
- Gateway password helpers currently live in `session/auth.ts`; move to a shared
  location if dashboard auth needs them later. Do not duplicate password formats.
